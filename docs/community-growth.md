# Comunidade e crescimento publico

Seven deve crescer por utilidade real, documentacao clara e contribuicoes honestas.
Este plano existe para orientar divulgacao, feedback e reputacao publica sem usar
atalhos artificiais.

## Principios

- Repositorios devem entregar algo executavel, documentado ou estudavel.
- Estrelas, forks e discussoes devem vir de pessoas interessadas no projeto.
- Pull requests devem corrigir, melhorar, documentar ou validar algo concreto.
- Issues devem registrar problemas, ideias, decisao tecnica ou trabalho verificavel.
- A autoria de Gabriel Barcelos deve permanecer clara em docs, releases e assets.

## Caminhos de contribuicao

1. Melhorar exemplos `.sev` com casos pequenos e verificaveis.
2. Expandir a biblioteca padrao com modulos coerentes.
3. Escrever guias curtos para frontend, backend, runtime e compilador.
4. Abrir discussoes publicas sobre sintaxe, ergonomia e tooling.
5. Publicar releases pequenos com changelog, hashes e estado de prontidao.

## Reputacao tecnica

Seven deve buscar reconhecimento pelo que entrega:

- especificacao clara;
- compilador e runtime auditaveis;
- exemplos fullstack;
- identidade visual consistente;
- roadmap publico;
- referencias oficiais de autoria;
- evolucao por pull requests revisaveis.
